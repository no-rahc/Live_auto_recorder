# Operations Center

`/operations`는 녹화 서버의 안전성과 유지보수를 위한 운영 화면입니다. 로컬 전용 모드에서는 별도 로그인 없이 사용할 수 있습니다.

## 저장소 보호

기본값은 남은 공간 10% 경고, 5% 신규 녹화 차단입니다. 차단은 기존 녹화를 강제로 삭제하지 않으며, 새로운 자동·수동 녹화 시작만 막습니다.

정리 방식:

- **보관 기간**: 지정한 일수보다 오래된 영상 삭제
- **총 용량**: 전체 녹화 파일이 지정 용량 이하가 될 때까지 오래된 순서로 삭제
- **여유 공간 회복**: 경고 기준 이상의 여유 공간이 확보될 때까지 오래된 순서로 삭제

항상 제외되는 항목:

- 현재 녹화 중인 파일
- RecorderManager가 사용 중으로 표시한 파일
- 기본 10분 이내에 수정된 파일
- 녹화 경로 밖의 파일

자동 정리는 기본적으로 비활성화되어 있습니다. 먼저 미리보기 결과를 확인하세요.

## 녹화 건강 상태

10초마다 다음 정보를 확인합니다.

- 녹화 프로세스 생존 여부
- 현재 파일 크기와 증가 속도
- 마지막 파일 수정 시각
- FSM 상태와 예약 상태
- 자동 재연결 횟수

기본 120초 동안 파일이 증가하지 않으면 멈춤으로 판정합니다. 자동 재연결은 기본 최대 3회이며 채널별 잠금과 재시도 대기 시간을 사용해 반복 재시작을 제한합니다.

## 녹화 기록과 완료 파일 검증

녹화 이벤트는 기존 `recording_history.jsonl`과 함께 `/app/json/recordings.sqlite3`에 누적됩니다. JSONL은 최근 상태 호환용으로 유지되지만 운영 화면의 장기 기록과 통계는 SQLite를 사용합니다.

정상 종료된 녹화는 백그라운드에서 `ffprobe`로 영상 스트림과 재생 시간을 확인합니다. 검증이 실패하면 FFmpeg stream copy remux를 한 번 시도하고 복구한 파일을 다시 검사합니다. 원본 교체는 복구 파일이 검증된 경우에만 수행합니다.

운영 화면의 **녹화 기록** 탭에서 다음 상태를 확인할 수 있습니다.

- 녹화 완료·실패
- 파일 검증 정상·복구 완료·손상·파일 없음
- 외부 보관 대기·완료·실패
- 수동 검증·복구 재실행

재연결 때문에 같은 라이브가 여러 파일로 나뉜 경우에는 기본 **방송 단위** 보기에서 하나의 방송으로 묶어 표시합니다. 같은 채널에서 짧은 시간 안에 다시 시작하더라도 제목이 다르면 별도 방송으로 처리합니다. 방송 상세에서 원본 세그먼트를 확인할 수 있고, 2개 이상이면 FFmpeg stream-copy concat으로 수동 합치기를 실행할 수 있습니다. 자동 합치기는 기본 비활성화이며 원본 세그먼트 삭제도 기본 비활성화입니다.

녹화 실패는 저장된 오류와 redaction된 프로세스 stderr를 바탕으로 인증/쿠키, 요청 제한, 네트워크, 저장 공간, 파일 권한, 필수 도구 누락, 스트림 사용 불가, 미디어 오류 등으로 분류해 조치 방법과 함께 표시합니다.

## 후처리 작업

기존 후처리 진입점을 감싸 작업 상태를 기록합니다. 실행 중 작업은 취소 요청이 가능하고 완료·실패·취소 작업은 재시도할 수 있습니다. 재시도 시 원본 경로가 이동되었으면 녹화 저장소에서 같은 파일명을 한 번 더 찾습니다.

## 알림 센터

녹화 시작·완료·실패, 파일 검증, 저장소 경고와 외부 보관 결과를 전송 대기열에 넣습니다. 실패한 전송은 지수 백오프로 재시도하며 최대 시도 횟수와 조용한 시간대를 설정할 수 있습니다.

Telegram과 Discord는 기존 설정을 사용합니다. 추가 이벤트 웹훅은 운영 화면에서 등록할 수 있으며 secret을 지정하면 요청 본문에 대한 HMAC-SHA256 값을 `X-LAR-Signature-256` 헤더로 전송합니다.

## 외부 보관

외부 보관은 `rclone`을 사용합니다. Docker 이미지의 기본 설정 경로는 `/app/json/rclone.conf`이며 `data` 볼륨에 함께 보존됩니다.

예시 remote:

```text
gdrive:LiveAutoRecorder
s3:recording-bucket/live
webdav:archive
```

`rclone config`로 작성한 설정 파일을 호스트의 `data/rclone.conf`에 두고 운영 화면에서 remote 경로를 지정합니다. 자동 보관을 켜면 녹화 파일 검증이 `정상` 또는 `복구 완료`일 때 업로드 대기열에 추가합니다. 원격 크기 검증이 성공한 경우에만 `업로드 후 로컬 삭제` 옵션이 실행됩니다.

## API 토큰과 자동화

웹 관리 화면은 로컬 전용이라 로그인 없이 열리지만, 자동화 전용 엔드포인트는 `lar_` 접두사의 API 토큰을 계속 요구합니다. 토큰 원문은 생성 직후 한 번만 표시되며 SHA-256 해시만 SQLite에 저장합니다.

권한 범위:

- `read`: 상태와 녹화 기록 조회
- `control`: `read` + 채널 수동 시작·중지
- `admin`: 향후 관리용 전체 범위

지원 엔드포인트:

```text
GET  /api/v3/automation/status
GET  /api/v3/automation/recordings
POST /api/v3/automation/channels/{channel_id}/start
POST /api/v3/automation/channels/{channel_id}/stop
```

요청 헤더:

```text
Authorization: Bearer lar_...
```

토큰에는 만료일과 마지막 사용 시각이 기록되며 운영 화면에서 즉시 폐기할 수 있습니다.

## 백업과 복원

기본 백업에는 다음 파일이 포함됩니다.

- `config.json`
- `channels.json`
- `operations_v2.json`

민감정보 포함을 선택하면 쿠키와 알림 관련 secret 등 로컬 데이터에 저장된 민감정보도 포함될 수 있습니다. 복원 직전에는 현재 상태를 담은 `pre_restore` 백업을 자동 생성합니다.

`recordings.sqlite3`, `platform_v3.json`, `rclone.conf`는 운영 데이터이므로 호스트의 `data` 디렉터리 백업에 포함하는 것을 권장합니다.

### SQLite 자동 보호

녹화 카탈로그는 설정 백업과 별도로 SQLite backup API를 사용해 기본 24시간마다 `data/database_backups`에 스냅샷을 만듭니다. 기본 7개를 보관하며 백업 전·후 `PRAGMA integrity_check`를 수행합니다. 실행 중 DB는 주기적으로 무결성 검사와 WAL checkpoint를 수행하고 문제가 발견되면 알림 대기열에 `database.integrity_failed` 이벤트를 추가합니다. 운영 화면의 **시스템 점검**에서 즉시 백업과 현재 무결성 상태 확인도 가능합니다.

## 시스템 점검과 유지보수

운영 화면의 **시스템 점검** 탭에서 다음 항목을 한 번에 확인할 수 있습니다.

- FFmpeg, Streamlink, ytarchive, rclone 설치 상태
- 녹화 저장소 쓰기 권한과 남은 공간
- SQLite 무결성
- CHZZK/YouTube 쿠키 상태
- Telegram/Discord 알림 구성 여부
- CHZZK/YouTube HTTPS 연결
- 현재 버전과 GitHub 최신 Release

각 항목은 정상·경고·문제로 표시하고 문제일 때 조치 방법을 함께 제공합니다. 최신 버전 확인은 알림만 제공하며 자동 업데이트는 수행하지 않습니다.

쿠키 상태는 기본 6시간 간격으로 확인합니다. YouTube Netscape 쿠키의 만료 시각을 확인해 만료 또는 7일 이내 만료를 경고하고, CHZZK 인증 쿠키는 필수 인증 값 존재 여부와 장기간 갱신되지 않은 파일을 경고합니다. 실제 플랫폼 로그인 정책에 따라 쿠키가 더 일찍 무효화될 수 있으므로 녹화 실패의 인증 분류와 함께 판단합니다.

## 채널 규칙

채널별로 다음을 지정할 수 있습니다.

- 제목 포함·제외 단어
- 허용 카테고리
- 허용 요일과 시간대
- 녹화 시작 지연
- 화질 덮어쓰기
- 최대 녹화 시간
- 최소 녹화 시간 미달 파일 자동 삭제

규칙으로 차단된 자동 감시는 조건이 다시 허용되면 자동으로 재개됩니다. 메타데이터가 아직 로딩 중일 때는 제목·카테고리 규칙을 성급하게 적용하지 않습니다.

## 감사와 보안

운영 정책 변경, 저장소 차단, 자동 재연결, 정리, 백업·복원과 쓰기 API 요청을 `/app/json/operations_audit.jsonl`에 기록합니다. 요청 본문과 쿠키·토큰·웹훅 값은 기록하지 않습니다.

응답에는 클릭재킹, MIME 스니핑, 과도한 referrer 전송을 막는 기본 보안 헤더가 추가됩니다. 웹 콘솔은 호스트의 `127.0.0.1`에만 게시하는 것을 전제로 합니다.
