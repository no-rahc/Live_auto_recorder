# Operations Center

`/operations`는 녹화 서버의 안전성과 유지보수를 위한 운영 화면입니다.

## 저장소 보호

기본값은 남은 공간 10% 경고, 5% 신규 녹화 차단입니다. 차단은 기존 녹화를 강제로 삭제하지 않으며, 새로운 자동·수동 녹화 시작만 막습니다.

정리 방식:

- **보관 기간**: 지정한 일수보다 오래된 영상 삭제
- **총 용량**: 전체 녹화 파일이 지정 용량 이하가 될 때까지 오래된 순서로 삭제
- **여유 공간 회복**: 경고 기준 이상의 여유 공간이 확보될 때까지 오래된 순서로 삭제

항상 제외되는 항목:

- 현재 녹화 중인 파일
- RecorderManager가 사용 중으로 표시한 파일
- 기본 10분 이내에 수정된 파일
- 녹화 경로 밖의 파일

자동 정리는 기본적으로 비활성화되어 있습니다. 먼저 미리보기 결과를 확인하세요.

## 녹화 건강 상태

10초마다 다음 정보를 확인합니다.

- 녹화 프로세스 생존 여부
- 현재 파일 크기와 증가 속도
- 마지막 파일 수정 시각
- FSM 상태와 예약 상태
- 자동 재연결 횟수

기본 120초 동안 파일이 증가하지 않으면 멈춤으로 판정합니다. 자동 재연결은 기본 최대 3회이며 채널별 잠금과 재시도 대기 시간을 사용해 반복 재시작을 제한합니다.

## 후처리 작업

기존 후처리 진입점을 감싸 작업 상태를 기록합니다. 실행 중 작업은 취소 요청이 가능하고 완료·실패·취소 작업은 재시도할 수 있습니다. 재시도 시 원본 경로가 이동되었으면 녹화 저장소에서 같은 파일명을 한 번 더 찾습니다.

## 백업과 복원

기본 백업에는 다음 파일이 포함됩니다.

- `config.json`
- `channels.json`
- `operations_v2.json`

민감정보 포함을 선택하면 쿠키, 로그인 계정과 Telegram 설정도 포함합니다. 복원 직전에는 현재 상태를 담은 `pre_restore` 백업을 자동 생성합니다.

## 채널 규칙

채널별로 다음을 지정할 수 있습니다.

- 제목 포함·제외 단어
- 허용 카테고리
- 허용 요일과 시간대
- 녹화 시작 지연
- 화질 덮어쓰기
- 최대 녹화 시간
- 최소 녹화 시간 미달 파일 자동 삭제

규칙으로 차단된 자동 감시는 조건이 다시 허용되면 자동으로 재개됩니다. 메타데이터가 아직 로딩 중일 때는 제목·카테고리 규칙을 성급하게 적용하지 않습니다.

## 감사와 보안

운영 정책 변경, 저장소 차단, 자동 재연결, 정리, 백업·복원과 쓰기 API 요청을 `/app/json/operations_audit.jsonl`에 기록합니다. 요청 본문과 비밀번호·쿠키·웹훅 값은 기록하지 않습니다.

같은 IP의 로그인 실패가 10분 동안 5회 누적되면 HTTP 429로 일시 차단합니다. 응답에는 클릭재킹, MIME 스니핑, 과도한 referrer 전송을 막는 기본 보안 헤더가 추가됩니다.
